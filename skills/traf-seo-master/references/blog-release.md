# Release checks for blogs, documentation and archives

Use the site's real publication rules and the actual release build. Before changing a template, capture its served URL, status, canonical, robots, alternates, raw HTML, and relevant sitemap section. Record the branch or image and the tenant, locale and CMS configuration. Run a small representative matrix through the public route or matching local build before changing the rest of the family.

| Surface | Evidence required |
| --- | --- |
| Locale and category archives | For a deliberately available but empty archive, use crawlable `200` with `noindex, follow` and exclude it from sitemaps and hreflang. Base this on complete eligible public content for that archive. Recheck the first eligible publication and the removal of the last item. A failed or partial CMS read is an availability error. Return a temporary error for a dependent sitemap when inventory cannot be read, and verify unrelated sections still serve. |
| Pagination | Fetch page 1, a middle page, the last page and an out-of-range page. Each valid page has a stable URL and self-canonical. Verify the next and previous `<a href>` links in raw HTML and keyboard navigation with JavaScript disabled. Mark the current page for assistive technology. Redirect equivalent aliases of page 1 to its canonical URL. |
| Legacy and duplicate routes | Inventory real legacy URLs before adding redirects. Check unprefixed, duplicate locale, mixed-case slug and already-canonical URLs. Use a one-hop permanent redirect only to a verified equivalent public page on the same tenant. An existing exact slug takes precedence. Preserve meaningful query state, prevent loops and leave unknown URLs as real 404s. |
| Article links and code | Keep HTML and exported Markdown aligned. Remove internal campaign-only parameters on explicitly identified routes. Preserve functional referral, invite, signed-access and pagination parameters, fragments, external attribution and code blocks. Point navigation to the final locale URL. Display raw API endpoints as code when they are examples. Link readers to the corresponding docs when they need navigation. Verify analytics consent, event attribution and that a click leaves the acquisition source intact. |
| Documentation HTML and FAQ | Inspect initial HTML and mobile interaction. Native disclosures keep approved answers in the document before JavaScript. Check headings, keyboard navigation and valid interactive markup. Place the caption directly inside its figure in the first or last position. Check that any structured data matches visible answers and current engine eligibility. Google discontinued FAQ rich results in May 2026. |
| Article images | Use approved tenant-owned origins and paths for the optimizer. Prove that an actual image request returns the expected format and a suitable size for the viewport. Set dimensions and meaningful alternative text where needed. Prioritize the above-the-fold image when evidence identifies it as the LCP element. Lazy-load the rest as appropriate. Verify original fallback, CDN/cache behavior, layout shift and the observed LCP change. |
| Own-product cost routes | If an existing page presents the product's own rates, make it an explicitly labeled estimator with consistent title, H1, breadcrumbs and structured data. Verify the price units and the rendered totals. Only compare deltas when a second product and a comparable rate exist. Treat missing copy and unresolved translation keys as rendering failures. |

For editorial repair, keep revision and rollback evidence. Inspect broken links, unintended duplicate headings, malformed code blocks and obsolete placeholders. Validate rendered output and runnable examples after the edit. Establish the affected tenant and URL population before making bulk CMS changes.

## Optional search notifications

When the relevant engine supports IndexNow, validate the exact public hostname, publication locale, key location and canonical URL allowlist. Read back the configured key file through the production-equivalent proxy and public asset guards. Require `200` and the expected body, with unrelated and wrong-host keys rejected. Test publication, substantive public content changes, unpublication, deletion and slug changes. On a slug change, evaluate both the old and new public URLs. Use the same eligible canonical URLs as the public renderer. Include rendered tool, media and structured-data changes where they affect what users see. Keep drafts, unchanged saves, preview URLs, account routes and other tenants outside the submission scope.

Use an event fingerprint and deduplication, honor the full server `Retry-After` interval, and retain redacted receipts per URL or batch. If delivery is required across restarts, use the project's durable queue or outbox and reconcile unknown outcomes before a replay. Keep live writes behind the exact authorized scope and verify one real permitted canary. Record submission, ownership verification, crawler observation and indexing separately. IndexNow `202` means the key is pending verification. For Google, use sitemaps, crawlable links and the verified Search Console property for ordinary content. Google's Indexing API has separate eligibility.
