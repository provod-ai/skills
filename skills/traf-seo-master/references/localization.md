# Localized acquisition and changing facts

Take actual supported locales and regional product availability from current owning manifests/source, not a copied language list. English worldwide still contains distinct markets and SERPs. Country is not query language, and a translated phrase is not observed local demand. Preserve authentic query spelling, accents, versions and provider scope; don't generate synthetic translated keyword corpora and label them researched.

Maintain stable content/intent/entity identity plus locale/market/URL, translation family, source revision, local facts/claims and update status. Equivalent user tasks can need different examples, prices, screenshots, product steps or source evidence. Source fact changes identify every dependent locale/asset; changing a display date alone is not maintenance. Unknown facts stay unknown rather than copying a no-longer-valid English claim.

Use separate crawlable URLs, appropriate self-canonical, reciprocal/self hreflang and an optional x-default selector. Verify the actual rendered links/metadata and index evidence. Don't canonicalize every translation to English or force IP/browser-language redirects that trap visitors/crawlers. Region variants need real user/product differences; each country name does not justify an interchangeable doorway page.

Prove the complete localized path: relevant search need -> useful page/tool -> accessible signup/access/payment where relevant -> useful result -> appropriate support and measurement. Prepare architecture for all actual locales, then qualify waves by observed demand, product readiness and replicated acquisition. Language count is not a traffic multiplier; account for displacement/overlap when measuring net gain.

Use the existing localization workflow first. Available tools such as [Tolgee](https://github.com/tolgee/tolgee-platform) or [Crowdin MCP](https://store.crowdin.com/crowdin-mcp-server) are optional integrations with their own identity, price/usage and file/API contracts. An installed translation SDK or generated file does not establish accepted routes or native-language quality. Preserve the owner's selected strong model and use qualified native review where it materially changes correctness.

Output locale/source dependency map, demand evidence, adapted complete assets, technical/browser checks and page-age acquisition cohort. List missing product/locale paths precisely; don't block useful independent English work while one locale is unavailable. Sources: [Google multilingual sites](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites), [localized versions](https://developers.google.com/search/docs/specialty/international/localized-versions).
