# Images, previews and media search metadata

Use media because it helps the actual user task: explanatory diagrams, real output examples, product screenshots and readable share previews. Keep the asset's source, version, role, dimensions, content relationship and freshness. Alt text and captions describe real content; filenames/metadata cannot manufacture evidence of a feature or result.

For existing images inspect accessibility, sizing/cropping across actual viewports, responsive delivery, compression/format, loading priority and layout stability. Verify social/open-graph previews when relevant, without pretending a preview creates search traffic. Preserve original owner assets and user filenames; derive copies only in the approved output area. Avoid putting text-critical details into unreadable tiny images.

For CMS article images, verify the optimizer's tenant allowlist and the actual responsive response. [Blog and documentation release checks](blog-release.md).

Use existing host image/design tools or qualified deterministic vector/code operations according to the real task. New bitmap generation/editing may require a named provider/model/account and spend boundary; do not assume a stored image key or catalogue entry enables a paid run. Respect the current task's one-generation/no-replay or source constraints where supplied. Never turn an editing request into unrelated media production.

If the task includes existing video/media pages, use current feature-specific guidance for crawlability, structured data and supported indexation. This module does not activate a social short-video production campaign; explicit project exclusions remain in force. Media generation methods are separate provider contours and do not inherit text-model credentials/authority automatically.

For visible media/UI changes inspect the actual result in the target page with screenshots, relevant interactions and console errors. Existing asset metadata, generated-file existence and a passing build are intermediate. A missing tool or unavailable visual check stays explicit.

Deliver actual usable assets where requested, their source/derivation and page integration checks, plus the measured or still-unproven discovery/use contribution. Sources: [Google image SEO](https://developers.google.com/search/docs/appearance/google-images), [Google video guidance](https://developers.google.com/search/docs/appearance/video), [Google structured data](https://developers.google.com/search/docs/appearance/structured-data/intro-structured-data).
