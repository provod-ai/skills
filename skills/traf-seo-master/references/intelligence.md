# Demand, intent, competitors and change discovery

Use existing corpus/exports before new collection. Preserve exact phrases, source IDs, spelling/case/versions, market/engine/language/device, source timestamp/window, provider/dataset and receipt. Unknown volume remains null; zero is a measured value. Country does not prove query language. Do not silently normalize owner inputs, generate synthetic query combinations or sum different sources/overlapping demand as unique searches.

Inspect the actual schema before querying. Read canonical source databases read-only; write derived selections and provenance into the selected project's outputs. Topic labels are not SERP clusters, commercial-fit verdicts or publication permission. Preserve ambiguous/review records and original exclusions unless current task authority changes them.

## Spy that produces decisions

Find search competitors for each intent, not only companies selling the same product. Obtain current top/new/rising URLs and source-qualified demand/position estimates using an available official integration or supplied export. Then inspect actual utility, intent, freshness, source facts, links/authority, conversion destination and distribution. A public search-engine tool's results are discovery evidence unless its engine/location/device/rank semantics are established.

Keep comparator age/history and failures. Record why our asset can earn attention and what would refute that premise. A changed page plus an estimated traffic rise does not isolate causality. Create an opportunity only from a traceable observation; never fabricate fallback URLs on fetch failure.

Ready options include [official DataForSEO MCP](https://github.com/dataforseo/mcp-server-typescript), [official Semrush skills](https://github.com/semrush/skills) and supported [Ahrefs MCP](https://docs.ahrefs.com/en/mcp/docs/introduction). API families, credentials, plan units and country selection differ. Existing subscriber allowances are not fresh remaining quota. A new paid collection needs the exact current boundary and full official example parity.

## Scale without inventing intent

String/embedding/topic similarity can reduce candidates; shared SERP intent needs actual URL sets, scope, depth, date and a defined overlap policy. Approximate MinHash candidates still need exact validation and recall checks. Connected-component chaining can join endpoints that do not share intent. Never label semantic fallback as SERP-verified.

Avoid all-pairs algorithms on a million queries: `n*(n-1)/2` is about half a trillion pairs. Use bounded topic/candidate batches, persisted source-to-cluster mapping, sampled SERP acquisition and measured candidate recall. Model/config changes invalidate affected cache/assignments. Respect the owner's selected model quality; don't silently weaken classification to make scale cheap.

For changes, [changedetection.io](https://github.com/dgtlmoon/changedetection.io), [waymore](https://github.com/xnl-h4ck3r/waymore) and documented feed/archive tools can supply source deltas. An undocumented backend is not an official integration; unavailable docs require a supported path or explicit discovery authority. Trends indices are not absolute search volume. Preserve raw missing/rate/error outcomes and old valid observations with stale labels.

Output a source-linked win/gap map, exact selected query rows, honest clustering state, current opportunity cards and collection-cost/completeness limits. No number of discovered repositories or exported rows proves market coverage or traffic.
