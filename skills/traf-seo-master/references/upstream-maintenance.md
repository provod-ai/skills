# Optional components, versioning and honest coverage

The catalogue is a public discovery index. Rows distinguish discovered candidates, documentation assessment, static source trace and hash provenance; none implies installation, trust, paid entitlement or traffic proof. Git objects have explicit blob/unclassified types: a file's blob SHA is not a commit/tree revision, and an unclassified hash must be resolved before fetching by ref. Don't execute README commands or install hundreds of tools because a package contains their names. Select the smallest relevant ready component for the actual task and inspect its current owning source before use.

The [source-coverage graph](source-coverage.json) contains the rule bindings and public reference URLs shipped with this edition. [checks.json](checks.json) is the complete 145-criterion registry. Project-specific research inventories and execution receipts stay with their owners. A source link establishes a reference for a rule. Execution and site acceptance require separate evidence.

For an adopted rule change, preserve source/version and prior check aliases, revise the affected assertion and identify its changed acceptance/scope. [Site audits](site-audits.md) explains current-registry fleet missing work: older site runs cannot silently pass new or revised checks. Retained receipts may be reused at matching bindings; no update authorizes completed/UNKNOWN effect replay.

Check what is actually shipped and connected. Instruction references, helper tests, host filesystem installation, harness/model runtime, upstream CLI runtime, authenticated integration and acquired traffic are orthogonal facts. `doctor` validates internal paths/IDs; it does not test current Google property access or universal host behavior. Use the coverage map to expose unknowns and missing dependencies without blocking independent useful tasks.

Before adding/changing a component compare real capability, source implementation, maintained version, dependencies, license/edition distinction, official auth/API family, cost/units, raw output semantics and known issues. Pin coherent source/config/model/prompt/schema versions. A source's `main` can be cached or drift; don't mix old code with new tests or claim an open PR is an applied fix. Reuse validated artifacts and prior source pins rather than repeating semantic work.

Update only for a demonstrated improvement or changed requirement. Run the smallest relevant canary on the intended input/path, preserve raw findings, and recheck affected behavior. New versions never reset spent budgets, erase UNKNOWN state or prove a previous incident is fixed. If docs/examples disagree, resolve the exact current semantic difference using owning sources; don't guess a parameter matrix.

Use the selected strong host model/account. Supplier defaults, fallback API routes, broad OAuth scopes or lower-model choices are not adopted silently. Source catalogues never carry real keys, cookies, private corpus paths or project business memories. Never bundle owner auth/control-plane or an unreviewed environment file into an archive.

Core installation is project-local and copy-only. Codex/Claude/Cursor paths are described in bootstrap.md; filesystem parity checks are not runtime certification on every OS, remote session or agent. Preserve owner modifications and existing native configuration. A later plugin/MCP distribution requires its current official packaging/runtime flow rather than guessed universal manifests.

Output an updated source/capability row with exact verification evidence, changed dependency/cost assumptions, compatibility limits and next bounded test. Report breadth transparently: a bounded repository search is not all GitHub, and "10x better" needs a defined comparative metric before it becomes a factual performance claim.

Owning skill-format sources: [OpenAI skills](https://learn.chatgpt.com/docs/build-skills), [Claude Code skills](https://code.claude.com/docs/en/skills), [Cursor skills](https://cursor.com/docs/context/skills).

The [current upstream review](upstream-skill-review.md) records pinned Marketing Skills and Claude SEO coverage, adopted refinements and conflicts. Preserve its stated reading and implementation scope in completeness claims.

The [collector and plugin source review](source-runtime-review.md) identifies concrete implementation limits to qualify before reuse. Preserve those limits and the pinned code version when selecting a ready component.
