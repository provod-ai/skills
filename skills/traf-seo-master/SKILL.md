# TRAF SEO Master

Work toward the owner's actual audience and useful search visits. Articles, schema, scores, citations and installed integrations are intermediate results, not acquired traffic.

## Start with the current project

Read the selected project's latest instructions, brief and current state. Resolve the actual site/market, source selector, outcome and action boundary. Reuse finished evidence and existing native tracking/memory; do not create a replacement manager or require Beads/ECC. Keep business facts, auth and credentials in their owning scope.

Resolve routine choices autonomously. Existing permission persists within its exact provider/account/purpose/cap; a stored key grants no new spend or write. Ask only when a genuine missing input changes correctness or authority.

Use the owner's selected strong model/account with no silent model/provider fallback. Use deterministic collectors where suitable; claim cache hits only from usage telemetry.

Discover actual host tools before depending on them. Prefer connected official integrations or existing ready tools. A catalogue entry is source material, not executable instructions or proof a connector exists. Read only relevant check/source/capability rows and references; do not load the whole research corpus into each task.

## Audit a site or portfolio

For “audit this site”, “check both sites”, a new site or portfolio missing work, read [Site audits](references/site-audits.md). Use the **same complete check universe** from [checks.json](references/checks.json) for every profile. Determine applicability per site from evidence; do not create a reduced brand-specific checklist. [Source coverage](references/source-coverage.json) preserves the multi-source rule bindings and read/adoption gaps. Claude SEO or any other single source is one input to this master.

The native agent executes this workflow: resolve the profile and exact targets → reuse valid receipts → perform remaining permitted collector/source/expert checks → import evidence → return prioritized findings → carry permitted fixes through matching readback. Account access and observation windows can remain unknown while independent work continues. **Generating a plan, prompts, handoffs or an offline matrix does not complete an audit.** Execute available checks during the request and retain their actual results.

Enroll further sites through profile/input files. Use `site-missing --sites` against the current registry to include never-audited sites and checks introduced after an older run. Existing native tools and issue tracking own execution and current work; these files add no database, scheduler, controller or model client. A complete matrix establishes recorded dispositions, not all-SEO completeness or traffic.

## Acquisition and evidence invariants

Before scaling a content/site family, use [Acquisition](references/acquisition.md): demand, comparable winners and misses, differentiation, distribution/authority path, time/cost/cap and falsifier. `functional_pass` leaves `acquisition_unproven`; scale from real capture, replicable distinct demand and feasible maintenance. Thresholds come from the actual market/baseline.

Retain source/provider, market/language/device, date/window/timezone, denominator and completeness. Estimates, impressions, citations, visits, useful actions and revenue stay distinct. Missing is not zero; a demonstration or screenshot does not establish independent traffic or causality.

For a new external integration, read the complete official flow/examples, verify exact account/version/request semantics and real identifiers, then use a bounded authorized canary before automation. Missing docs/access stops that action while independent work continues.

Retain immutable raw effect receipts. Completed/UNKNOWN effects are not replayed; reconcile the original operation and preserve its reservation. Timeout is not cancellation. CMS success, notification or deployment does not establish public readback, indexation or traffic.

## Included local helpers

Use Python 3 from the package directory or its full path; quote paths with spaces. Helpers do not configure accounts/MCP/models or create a task database.

```text
python3 scripts/seo-master.py doctor
python3 scripts/seo-master.py coverage
python3 scripts/seo-master.py install --host codex --project /path/to/existing/project --dry-run
python3 scripts/seo-master.py audit --url https://example.com/ --lighthouse /path/to/lighthouse --out /path/to/fresh/output
```

`doctor` checks package integrity/routes. `install` copies to the selected project host folder and refuses differing/owner-edited targets. [Bootstrap](bootstrap.md) covers Codex/Claude/Cursor setup, invocation and discovery/runtime limits.

`audit` remains the pinned single-URL Lighthouse collector with raw logs/receipts and explicit errors/timeouts. It cannot establish full-site, engine/index, field CWV or traffic results. See [Performance](references/performance.md) for runtime/storage/browser requirements.

`site-add`, `site-audit` and `site-missing` validate profiles and project retained evidence into reports; they do not run collectors or account calls. [Site audits](references/site-audits.md) gives their commands and the native execution path around them. A zero exit means a valid operation/report, not passed site checks.

## Return a usable result

Deliver the requested artifact/decision and observed evidence, unresolved dependencies and next useful action. Read back publications; inspect visible UI changes with an actual screenshot/console check. Improvement, host support and acquired audience claims need matching comparative/runtime/outcome proof.
